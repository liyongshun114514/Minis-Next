# SOUL 单一入口与提示词边界

## 配置范围

设置 → 系统提示词仅显示 SOUL（名称、头像、正文）。旧 AGENTS / CLAUDE 自动发现、作用域、预算与独占开关已移除；旧工作区深链仅打开 SOUL，不读取或改写旧文件。设备上已有用户文件及历史备份保留，不自动拼接到 SOUL，避免把旧冲突指令重新引入。

SOUL 正文接替旧 AGENTS 的权威头、`Instructions from:` 路径包装、原样正文及 native system 通道优先顺序。不再使用旧 SOUL 的中英文应用说明头、第二层正文标题或行清洗。非空正文独占用户提示词位置，生成的身份/元数据风格不再加入；空白正文保持身份回退。每回合快照供重试、候补和切模复用，子代理继续隔离。

详见 `agents-system-order.md`。头像/name 的存储和显示兼容不变；正文不会携带图像 data URI。

## 内置目录

`assets/prompt-catalog.json` 当前 353 个模板/片段：退休两个旧 SOUL 包装及旧工作区头，新增 SOUL 权威头。其它工具/语音/视觉/压缩/运行提醒的文本没有拼进 SOUL，也没有删除。

`PromptCatalogScope` 保留 7 个全局分组、26 个模板的分类元数据：身份与全局5、主系统提示词10、隐私1、记忆3、技能2、计划任务2、MCP3。它不再决定设置页的可见行；用户页只有 SOUL。旧内置编辑深链和按 id 覆盖仍由已有组件处理，退休 id 不再被调用，旧 PROMPTS.json 不清空。

## 权限与数据边界

- 原样正文可以包含 Markdown、标签、指令行；既不转义标签，也不删掉匹配某种句式的行。`soul.body` 配置保存仍为敏感操作，沿用用户批准、审计和可撤销流程。
- 权威措辞只描述这次模型请求的指令顺序；供应商服务端规则、实际工具门控和 Android Root/Shizuku/无障碍权限不由文件改写。
- Root 三态、拒绝/取消/超时不执行、敏感配置确认、Privacy Mode 掩码、记忆秘密保护、卸载占位写回拒绝等代码不变。
- 非空正文独占时，生成的身份/环境/旧元数据风格不进入该身份段，和旧 AGENTS 独占一致；不是省略验收。

## 回归

SOUL 原样/Unicode/长正文/空正文/无双重包装；设置仅单入口；自动工作区加载代码退休；每回合冻结、切模候补复用；OpenAI Chat/Responses、Anthropic API-key/OAuth、Gemini 原生请求体顺序和 user turn 不泄漏均有测试。既有 OAuth 公共构建缺标识的 skip 规则未变。
