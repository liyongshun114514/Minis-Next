# 1.6 / 51：统一提示词设置与消息、网页预览修复

## 设置入口

Settings → System Prompt 现在是统一目录：

- 名称、头像、全局 SOUL.md：沿用原编辑器与未保存保护；
- 工作区指令：AGENTS.md / CLAUDE.md 编辑与作用域设置移入此入口，旧路由仍兼容；
- 内置提示词：按场景分组、搜索、全文编辑、查看源码位置、恢复默认。

当前 Android 目录有 **355 个可编辑模板/片段**，包括主提示词、身份/风格、工具及参数描述、子代理、压缩、标题/分组、视觉、语音、调度/队列提醒、记忆/MCP/技能披露、44 条 Shell 语法说明/建议等。片段数不等于独立请求数；一些完整提示词由多个片段组成。

没有把所有场景文本强行拼入每次主对话请求。压缩、标题、语音、视觉等仍只在对应调用中生效；工具开关和实际设备授权仍由代码控制。顺带解除了浏览器关闭连带丢失记忆/子代理工具说明、记忆关闭连带丢失代理名册的旧文案耦合。

### 保存及兼容

- 用户覆盖存于 `minis-global/memory/PROMPTS.json`（Linux 挂载后 `/var/minis/memory/PROMPTS.json`），默认模板保留在代码和 `assets/prompt-catalog.json`。
- 默认无覆盖时按原文渲染；编辑后由实际生产调用点读取覆盖。恢复默认删除覆盖而非把默认复制为自定义。
- `{{slotN}}` 是运行时插槽，`{name}` 是身份替换位，默认中自带的 `{{result}}` 留给调度器。必须保留默认占位符及次数，可调整顺序；不递归展开动态值。
- 保存用同目录临时文件、fsync、rename；失败不截断旧文件、不发布新缓存。恢复默认删除失败也报告错误。
- 编辑器保存使用点击时快照；保存期间新输入仍为未保存。切换条目隔离状态，返回目录刷新“已编辑”标记。
- 内置 skill-creator 模板显式保存/恢复时同步已安装 `SKILL.md`；正常启动不会覆盖用户技能修改。用户自行导入的技能、实际记忆正文、子代理自定义指令仍属于各自用户数据，不复制为静态模板。
- 现有 memory 备份覆盖 PROMPTS.json，恢复后重新加载缓存。
- 已有 SOUL.md、工作区文件和聊天记录不迁移/不清空；iOS 参考实现、CLI --help、UI错误文案及构建期私有供应商标识不当作 Android 主提示词目录项。

校验：`python3 scripts/check-prompt-catalog.py` 检查唯一编号、默认文本、运行绑定、占位符以及源码位置；移动调用点后可用 `--refresh-sources` 只刷新位置。

## 中途发送消息消失

本轮发现的可见消息丢失路径不是只有 enqueue 一处：

1. 占位气泡先删，再依据早先快照决定是否补真气泡，条件变化时留下“回答在、用户行不在”；
2. DB 重建列表会抹掉尚未持久化的排队气泡；
3. 停止清理把旧整表快照写回，覆盖并发入队；
4. send / enqueue 分别读运行标志，收尾窗口中 enqueue 拒收但输入已清；
5. 队列恢复先挂起再普通写运行标志，可与新 send 双开循环；部分重试/继续收尾没有移交队列消费者。

修复增加 `QueuedMessageState`，原子交付自己的占位/真气泡，重载重挂队列；停止/流式更新改为基于当前列表的定点更新；enqueue 返回接受结果并提供普通发送回退；send 与队列恢复 CAS 抢占；各收尾路径补队列消费者。

**边界**：队列仍是 VM 内存数据，本轮没有实现进程死亡后的持久化恢复；相关纯逻辑/并发测试与源码接线守卫不等于实机长会话验收。

## 网页小窗口冻结

旧 Compose 轮询在工具块结束就取消，快动作后可能从未采到新帧；多个面各自采集互相串行等待；GPU 连续失败后永久降级也无法恢复。

现在由浏览器池共用 `BrowserLivePreview`：

- 一个生产者，界面通过 lease 订阅；最后一个订阅关闭即停止；
- 动作/目标变更触发采集，并在 250 / 900 ms 后补采，完成块后保留短暂刷新窗口；
- 前后台暂停/恢复，目标优先正在被驱动的标签，避免串旧 tab；
- GPU 失败采用冷却重试，成功重置；软件 detached 帧标记为未验证，而非假定实时；
- 预览缩至最长 720 px，工具正式截图仍保留原分辨率。

**边界**：没有安装运行 APK。GPU/虚拟显示/Chromium 合成像素、前后台真机表现、小窗口观感仍需设备验收。
