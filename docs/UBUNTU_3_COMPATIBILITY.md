# Ubuntu .3 compatibility fixes

This release repairs a shipped-image extraction regression, completes the native Composer UI, and shortens Root confirmation copy. Build/static/JVM acceptance is distinct from on-device validation.

## Shipped rootfs regression

The .2 image is generated by GNU tar with a leading archive-root directory (`./`). The production Kotlin extractor rejected that valid member before writing any files, even though Python archive inspection and APK signature checks passed. Fix: recognize archive-root **directory** members in `TarExtractor`; keep `SandboxDistribution.sanitizeArchivePath` and its existing rejection contract unchanged for all other members. No security filter is disabled.

Regression coverage uses the production Kotlin extractor with ordinary GNU/PAX/ustar members and, critically, the actual rootfs stream inside the final APK. `UbuntuBundledImageCompatibilityTest` checks shell/loader links, Python, dpkg state, toolset manifest and `UbuntuToolsetStatus` readiness without executing guest programs. CI sets `MINIS_BUNDLED_APK_REQUIRED=1`, explicitly passes the final APK, disables stale test-result reuse, and checks JUnit XML for zero skips/errors/failures **before** publishing a release artifact. A missing APK cannot count as success. Production retry/reset cleanup and the acceptance test share `GuestTreeFiles.deleteTree`, which uses `Files.walkFileTree` without `FOLLOW_LINKS` and unlinks guest symlinks rather than traversing their host-side targets.

## Composer longevity

Composer must be wired into the native chat screen and native model/thinking state. Do not rely on an external module recognizing an APK DEX hash or R8 symbol names. The previous source port deliberately reused the top-bar model selector instead of porting the bottom toolbar; this left an observable gap relative to the supplied MinisAllInOne UI. See `native-composer-port.md` for the current source-level feature matrix and verification boundaries. Menu actions, rename, model selection and thinking selection retain native callbacks; input and send behavior are not replaced.

## Root confirmation

The enable dialog is two sentences. Per-command confirmation shows the exact quoted argv, an expand control for long commands, one risk line, working directory/timeout, and only **allow this invocation** / **deny**. The underlying authorization manager is unchanged: default disabled, no session grant, only `ALLOW_ONCE` accepted, dismissal and timeout deny. No real Root/Shizuku operation is required to build or test these changes.

## Upgrade and recovery

Package ID and test-signing identity remain unchanged; versionCode increases to 38. Install over the previous Ubuntu APK rather than clearing data. Opening the terminal retries missing rootfs installation. Installation extracts into staging; the previous guest is preserved until extraction and readiness checks succeed. Do not clear app storage or automatically delete a previous rootfs/backup to work around this error.

## CI compiler memory

Run `40240713472` reached Kotlin IR lowering but failed with `OutOfMemoryError: GC overhead limit exceeded` in `compileGithubDebugKotlin`; the log also shows `compileGithubReleaseKotlin` active in the same invocation. Increasing only the Gradle heap did not ensure the separate Kotlin compiler had sufficient memory. The workflow now runs normal Debug JVM tests and the selected APK assembly as separate sequential Gradle invocations, with one worker, `--no-parallel` and `kotlin.compiler.execution.strategy=in-process`. The single shared heap is bounded to the lower of 6144 MiB and physical memory minus 2048 MiB; the runner memory and selected cap are logged. Final-APK extraction uses the same strategy. No app feature, dependency version, security check or acceptance criterion is removed to make compilation pass.
