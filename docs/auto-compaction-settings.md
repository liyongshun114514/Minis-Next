# 1.6.1 / 52：自定义上下文压缩与 CI 修复

## 使用

设置 → 上下文压缩（在模型组、Token 用量附近）：

- **自动压缩**：复用原有全局开关，与聊天菜单开关实时同步。
- **压缩阈值**：输入正整数 token 数；留空恢复原有模型容量默认策略。非法、零、负数或溢出输入不会覆盖旧值。
- **压缩模型**：选择已配置的文本输出模型，默认跟随当前对话模型。专用模型只用于摘要，不改变聊天模型、分组或会话绑定。

阈值统计当前出站请求估算 token，包括历史、系统提示词和工具 schema，并沿用 provider usage 校准。不是累计使用量，也不是精确 tokenizer 计数。在发送前、工具迭代边界检查；不会中断正在返回的单次请求。

显式自定义阈值在裁剪之前判定，避免被纯裁剪悄悄代替模型摘要。实际触发线取用户设置和原容量保护线的较小值；原本无摘要阈值的小窗口最多取窗口的 85%。关闭或不设自定义值保持既有容量保护语义（关闭开关不等于禁止原轮内容量救援）。

## 模型与边界

- 每次压缩冻结所选模型，递归拆分的各段使用同一 provider；摘要输出预算按压缩模型自己的窗口、输出上限计算。
- 专用模型条目删除、禁用、隐藏、类型不支持、无法输出文本或缺凭据时报告失败；保留设置，不静默改选、不路由到其他提供商。
- 默认跟随聊天模型的路径保留已有分组故障回退行为。设置专用模型的路径不参与该回退，不改聊天绑定。
- 仍使用现有摘要 marker、保留原始聊天记录、取消/超时/拆分深度与调用预算；每轮最多三次压缩及无进展保护不变。极低阈值若小于固定提示词本身，不能保证压缩后低于它。
- 设置存于 `minis_auto_compact_prefs` 普通 SharedPreferences；本次不扩展 provider 配置备份、跨平台或 minis-config 字段。
- 选择模型、打开页面不发起网络或计费请求；真正触发压缩时按所选模型正常消耗 token。
