# Android glass rendering

The Android UI uses Miuix `0.9.5-beta03`, which builds on Compose Multiplatform `1.13.0-rc01`; the app keeps matching `ui-test`/tooling artifacts. The beta03 migration follows [Mishka's migration guide](https://github.com/YuKongA/Mishka/blob/main/docs/miuix-glass-migration.md), checked against the beta03 Maven source artifacts. Preserve the opaque scene/page sampling split and root Scaffold overlay host. Dialog fields use native `GlassTextField` and its translucent default fill; caller validation, draft ownership and keyboard callbacks remain in the existing adapter. Existing native popup/sheet/button signatures remain compatible. The compact custom top-bar band already has no delayed visual-offset state and continues to sample one progressive blur; upgrading the library does not require replacing the app's compact measured bar layout.

## Backdrop ownership

- Chat records an **opaque, full-width message viewport** before message-column centering and gutters. Its toolbar, composer and two 36dp glass scroll buttons are separate from the recording. Both scroll buttons and the model-work/sub-agent status strips sample that viewport. The upper sub-agent and lower work content share one rounded `chatStatusBackground` panel using the composer's 20dp material and input-surface tint. No inner gap, stroke, shadow or second glass pass separates the rows. Their combined 65dp height matches the preview, which is bottom-aligned. The outer layout paints nothing and does not clip shadows. Height comes from current layout constraints and tool content from the same streaming snapshot as visibility/reserve, avoiding initial zero-height and delayed-collector flicker. Unsupported devices retain the same opaque input fill. Shared scrolling settings record their body for the same top-bar effect.
- `MinisGlassTopBar` draws one native progressive blur (`progressiveTextureBlur`, 48 dp `ProgressiveBlur.Top`) with the official 30% surface tint, sized to the measured foreground plus a compact 12dp overhang, so the band releases into the page without intercepting taps.
- `MinisGlassIconButton` samples `LocalMinisActionBackdrop`, which is provided only to sibling toolbar/FAB slots. Body descendants cannot consume the body capture. Buttons remain siblings of the band; neither samples itself. Use the native default fill only without a supported backdrop, and the same `GlassShadows.Regular` at the button and morph endpoint.
- Page bodies record once for their bars. Inside the capture, `LocalMinisActionBackdrop` is explicitly null: an inline glass member button must never sample a recording that contains itself (a cyclic RenderNode graph). `LocalMinisPageBackdrop` is only for relocated menus/sheets. The home accordion keeps stable item keys and placement motion; removed rows have no fade-out layer. Home rows use the native 20dp squircle surface inspired by Eta. Device validation is still required for native renderer stability.
- `MinisOverlayHost` supplies the root Miuix `PopupLayout`. `MinisSceneBackdrop` records the opaque scene while a same-window menu or dialog owns a lease, including exit. Only each popup panel samples and blurs that scene; the uncovered page stays sharp. There is no full-page blur overlay. Root popups and dimming are outside the recording. Menus use the complete scene when no explicit backdrop is supplied; explicit chat-menu backdrops remain message-only. Independent windows keep the readable native fallback rather than sampling another window.

`MinisSmallTopAppBar` deliberately shares `SettingsGlassTopBar`'s three-slot measure/place policy. Miuix 0.9.5-beta01's `SmallTopAppBarLayout` measures `actionIconsPlaceable` but never places it, hiding Mount Add / detail Save actions. Do not regress to that layout or its shadow-clipping `clipToBounds`. Reserve full action widths before ellipsizing the title; keep folder/permissions pages on the same `surface` background as the glass band.

## Menus

- Discrete/selection/context menus use native `GlassDropdownPopup` for the spring/arc opening and exit. Chat More, composer +, home Terminal, scheduled More, model-member More and skill menus use `GlassTransformPopup` with the actual glass-button anchor. Mark the icon with `glassPopupAnchorContent`, so its copied content does not expand from the entire button bounds. Opening and closing share the same origin. Every menu option uses an inset rounded-rectangle press plane matching `GlassPopupDefaults.ItemPressInset` / `ItemPressRadius`, including arbitrary-content action rows and the Send/Stop choosers; icon/text alignment remains unchanged. Grouped settings rows outside the popup retain their divider-aligned press planes.
- Independent icon actions use glass. Function-menu/sheet triggers opt into `menuMotion = true`; controls with long-press menus also use it. `minisJellyPress` observes without consuming clicks and delegates motion to Miuix `glassPress` (no custom spring or painted dim). Direct navigation/Search/Back stay still. `MinisDropdownPreference` binds native `BasicComponent` slots and `GlassPopupItem` to the shared exit/IME/scene contract; no library measurement/press code is copied.
- Miuix owns the glass surface, shadow, stroke and transitions. `MinisMenuPosition` translates existing physical left/right alignment and gaps into window coordinates. The wait-duration, sub-agent concurrency, provider network, response timeout, default/scope/provider route, bulk-route, exit-node, proxy-type and rule-format menus use the actual tap point, with the triggering control as a fallback for keyboard and accessibility actions. A provider route change is applied after native exit, because Follow Default removes its row and must not dispose the closing menu early.
- The host is first composed closed so native transitions animate on first open. Keep the caller composed through exit. Final-content disposal reads **current** visibility, sets the root `hostVisible` false and releases `mounted` before firing `onDismissFinished` once. Do not unconditionally restore `hostVisible = true` on a closing SideEffect: that can retain a collapsed surface/shadow over the restored button. The chat speed submenu opens from the finished callback.
- Composer Send/Stop choosers share this implementation, prefer placement above their button, avoid the IME, and do not take keyboard focus. Their existing preference writers and dismiss-tap guards remain unchanged.
- Preserve caller composition locals when moving menu content into the root overlay (session context, theme and interaction state).

## Floating composer and settings

The composer uses a 24dp glass shape, 10dp side gutters, 12dp bottom clearance plus the live navigation inset, and a 56dp minimum editor region that supports up to six text lines. Opening or closing the + menu leaves the composer at its measured size and position. The menu measures itself within the available safe area. Send uses neutral `onSurface` with a 10%-alpha idle fill.

The application uses the platform's unmodified Compose density and system font converter (the earlier 92% override has been removed). Typography no longer forces global left alignment, so native button/title alignment survives. The model picker uses the same platform density in the activity overlay. It uses a `surface` sheet and `surfaceContainer` cards, with a readable accent and radio-button semantics for selection. Its native glass host stays mounted through Miuix's exit animation so a management route opens after dismissal.

The message viewport extends behind the input overlay. Its list wraps short conversations and places them at the top of the viewport. `AlwaysStretchOverscrollBox` owns the only overscroll visual node. When the list can scroll, only its LazyColumn receives `withoutVisualEffect()` for events; the outer no-op scroller is disabled. For short content, only the outer scroller handles overscroll and the list receives no effect. Never feed the same gesture through both scrollers. Attaching the same visual node twice can bind its RenderNode to the short list and cut a pulled-down reply in half. Its bottom content padding includes the measured composer height and visible tool/status reserve exactly once. Tool/scroll controls are lifted by that same height. User bubbles use the neutral `surfaceContainerHigh`, not a primary-blue mix.

Section/dialog fields use neutral inset fills with rounded corners and a 16dp **inner** text margin; outer Card/block padding cannot replace it. Shared section captions use native `SmallTitle` (28dp text inset), Cards use a 12dp external gutter, and model-group detail uses `surface` behind `surfaceContainer` cards. Model members stay separate stable lazy items. Environment editor content/identity/prefill is retained until `onDismissFinished`, with a new draft key on the next session. The Root choice dialog places native `RadioButtonPreference` rows directly on the glass surface without a second filled Card. Each option clips its native press tint to `GlassPopupDefaults.ItemPressRadius` so all three use rounded rectangles, while their text alignment and draft-only selection stay unchanged. A 20dp-gap, equal-weight Cancel/Save row follows. The risk text scrolls while actions remain reachable. Skill-import tabs and provider API-format pickers use native `TabRowWithContour`. Native Cards own the outside corners of grouped choice rows; interior press edges stay square and flush with their divider. The row and its divider are one layout child, with the divider outside the input plane. Outer card padding is zero vertically; Preference content owns its breathing room. Sub-agent concurrency and wait duration use the shared native `GlassDropdownPopup` menu. The environment editor uses `MinisDialog` over native `GlassDialog`. Like the proxy editor, grouped labels and standard `DialogTextField` wells sit directly on the dialog surface, with no extra form Card or nested panel. Its body scrolls above two equal-width, filled `GlassDialogButton` actions; it retains the draft until native dismissal completes. The mount-picker introduction uses the same inset dialog and starts the guarded system picker only after dismissal. Both dialogs lease the scene only while their native content is mounted, including exit, and exclude the popup/scrim from sampling. Settings → System Prompt opens the SOUL editor immediately, with no intermediate SOUL directory row. Its authoritative body replaces the retired AGENTS/CLAUDE chain; legacy workspace links open SOUL without touching old files.

The thinking-level selector retains the original discrete particle slider (Canvas over `ThinkingSliderGeometry`, one Animatable in percent space, detent press/drag, release-only commit, cancellation without commit, accessible stepping and a disabled/reduced-motion clock stop). It now sits in a compact horizontal `MinisMenu`, up to 420dp wide and clamped to the safe area, with a close action. The chip records the real tap through `MinisMenuAnchor`; keyboard/accessibility uses its centre. The active point is stored relative to the control and reprojected whenever its window origin moves. A separate 1dp native `GlassTransformPopup` anchor is centred on that actual point, without first shifting it to the final panel edge. Final panel placement alone uses the control-row exclusion bounds. Opening from the + menu waits for that menu to finish exiting. The popup samples `chatTopBackdrop` and stays composed through native jelly exit. Its placement host ends 4dp above the measured + / model / send controls row (plus the native popup's safe margin), not above the entire composer. The panel can overlay the text editor while remaining just clear of those controls; longer drafts do not lift it above the input field. Closing or reopening the keyboard updates both the active point and placement boundary while the same popup stays open, so it follows the controls down or up rather than remaining at the old keyboard height.

Assistant responses use the original Minis body, thinking block and tool-fold rows. The Eta timeline projection and its answer typography are removed; no additional automatic folding is introduced. Stable lazy rows, the existing manual tool-fold preference, search and text selection remain. SOUL identity stays out of chat titles, waiting status and assistant headers. The revealed footer shows response latency and generated tokens per second only, without field labels. Timing is persisted; historical rows without timing show a dash instead of an invented value.

Both Compose and MinisTextKit selections use Android's native floating ActionMode menu, including native overflow/submenus. Partial-copy, whole-reply Markdown/rich/plain formats, read-aloud and table actions keep their original scope. LaTeX remains rendered by the existing local KaTeX pipeline, including inline, display, list and table expressions.

Manual transcript drags pause auto-follow immediately. A finger lift or nested-scroll end resumes following only at the actual bottom (`!canScrollBackward`), never merely inside the near-bottom FAB threshold; post-drag snap-to-bottom is removed. In-flight follow loops also yield to user intent. On phones, list/detail panes use the same 260ms `PageSlideMotion` push/pop translations as settings. The outgoing chat keeps its session content until the exit completes. Tablet panes retain short fades and 220ms bounds changes; sidebar resizing also uses a tween. Menu springs are unchanged.

## Native glass sheets and press boundaries

App bottom-sheet entry points use `MinisBottomSheet`, a lifecycle adapter around official `GlassBottomSheet`. A sheet samples its page recording (`LocalMinisPageBackdrop`, supplied by `MinisPageScaffold`/`SettingsScaffold` bodies) before the shared scene, so it never reads its own surface back into the blur. The thinking-level selector uses the separate horizontal popup described above. Miuix owns the layout, handle, scrim, blur material, surface clipping, drag/nested scroll, IME and predictive Back. Root scene sampling excludes all root overlays. A content-scoped lease survives native exit and releases on disposal; caller composition locals and `LocalDismissState` are preserved. Controlled `show` flows keep their finished callback; legacy `show=true` flows defer dismissal notification until native exit. Internal close buttons use that native dismiss state. Independent Android windows keep native `WindowBottomSheet` without unsafe cross-window sampling.

A page bar draws one native progressive blur (48 dp `ProgressiveBlur.Top`) tinted with 30% surface and a 12dp overhang. The compact extent deliberately narrows the official default band. The earlier 80% wash hid the texture it was meant to blur and read as a plain gradient. Bars fall back to `LocalMinisActionBackdrop`, and even short (non-scrollable) settings pages record their body, so the blur never silently degrades to the band brush.

Glass icon-button surfaces, shadows and anchor bounds stay in the resting coordinate plane; only glyphs receive `glassPress` while the native menu morph owns surface motion. `RichTitleAppBar` shares the progressive band; chat disables that inner band because `ChatGlassTopBar` already owns it. No rectangular Surface clips the shadows. Grouped settings press planes do not scale away from dividers; whole-card actions use native Card/Surface click APIs inside their clipping, not external clickable modifiers. Model-picker rows use rectangular press feedback at the seams. The tool-call capsule keeps one rounded silhouette for its fill, running shimmer and full-surface press tint. Minis Computer uses the native sheet material from header through footer and Miuix glass buttons for its actions. The custom title/actions occupy the native header slot, avoiding an empty native row plus a second header in the body.

## Settings and forms

Compact file, rootfs, scheduler, log, model and workspace bars use the same `MinisTopAppBar`. `MinisPageScaffold(overlapTopBar = true)` exposes the top inset to the actual scroll owner via `minisPageContentPadding` / `minisPageScrollPadding`, so the body can move beneath the band. Fixed media/embedded web viewports retain a safe top origin. A separate preview window owns its own capture; it never samples the activity window.

Settings and phone home/chat pushes translate in from the right and pop back using the same 260ms tween, with no spring. Tablet pane changes retain their short fades. Native `TabRowWithContour` is used for both MCP form/import and transport selection, with its default distinct track/selected fills; setting both to `surfaceContainer` hides the selected layer. MCP authorization uses native full-row `RadioButtonPreference` choices in one Card, retaining the existing login-busy guard. Provider API-key text shares the label field's horizontal text inset; URL and User-Agent rows have 16dp outer padding and a 10dp label/input gap. Browser settings use four themed cards, full-row radio choices, responsive width/height fields and wrapping presets. Confirmation and form dialogs share `MinisDialog` / native `GlassDialog`, including memory deletion and provider rule editing. `MinisTextButton` keeps native styling outside modal content and gives modal actions the filled `GlassDialogButton` treatment, preserving their callbacks and disabled state. Two-action dialogs use `MinisDialogActions` with equal-width bottom buttons, a 12dp gap, Cancel on the left and the main action on the right. The provider rule-format menu uses its actual tap in window coordinates; editor save/cancel is dispatched after native dialog exit.

The custom balance endpoint editor and request adapter are removed. The old field and cache enum remain as inert compatibility data for Room/backup reads; neither vendor selection nor live requests read the legacy endpoint. Automatic vendor/relay balance queries remain active.

## Fallbacks

On systems without runtime-shader support, use Miuix's opaque surface with its configured stroke/shadow and the toolbar's theme gradient. An independently hosted window dialog must not send its menu underneath itself in the activity overlay: it uses a non-focusable popup and does not sample a different window's scene.

## Regression checks

From the repository root:

```sh
python3 scripts/tests/test_native_composer_port.py
```

The source gate pins the sampling graph as well as the existing composer contracts. Android regression coverage lives in `MinisMenuPositionTest` and `MiuixMigrationUiTest` (scrolling menus, outside dismissal, repeated open/exit/submenu handoff, focused unsent draft, and toolbar fallback controls). They run through the Android CI regression task.

Source checks and JVM interaction tests are not a visual acceptance test. Inspect native glass, scrolling fade continuity, light/dark materials and button-to-menu morphing on a supported device.

## Group hierarchy

Model-group rows retain their original arrangement: name, modality icons and role badges share the heading row, followed by strategy/count and the single-line member preview. Only typography is smaller: native `body1` (16sp) for the medium-weight name and `footnote1` (13sp) for both detail lines, following the existing theme/system font scaling. Original spacing, colors, drag handle, tap, swipe actions and stable reorder keys are unchanged.

## Home controls, skills and terminal images

Home search/new-chat controls live in `MinisPageScaffold.bodyOverlay`, a sibling of the recorded body. The search field uses a native glass panel and transparent GlassTextField with a 16dp leading inset and 10dp icon/text gap. Generic menus are 164–252dp wide with 4dp outer vertical padding and 8dp row padding.

Skills navigation waits for the Add menu to finish exiting. The GitHub WebView is not included in a page glass RenderNode; release destroys it, and renderer loss replaces its keyed AndroidView once, then offers Retry. Native renderer stability still requires device validation. Stop-choice dialogs share MinisDialog/GlassDialog, keep their actions through exit and execute the selected stop scope only after dismissal.

APK builds carry `ubuntu-download.json` instead of a Linux filesystem. CI validates the separate preinstalled Ubuntu archive and extracts it using the production Kotlin parser before publishing an immutable `ubuntu-rootfs-v1-<run>` prerelease. No APK is published to Releases. Installation selects the newest complete image, validates its SHA-256/size, extracts to staging, and only then preserves/replaces the previous rootfs. Existing installations do not redownload. Reset uses the same transaction, leaving the prior guest intact if download or validation fails. Downloaded temporary archives are removed after success or failure.
